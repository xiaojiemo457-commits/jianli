# 简历生成（resume-builder）

## 定位

把「简历内容生产」与「简历排版渲染」拆开：本技能只负责收集真实素材、按 HR 筛选逻辑组织与表达内容、输出符合青柠简历 schema v3 的 JSON；排版、实时预览、PDF 导出全部交给 https://cvlime.github.io ，不重复实现任何前端渲染。

青柠简历的「恢复」功能接受一份纯简历对象 JSON（无外层包装），经 `normalizeResume` 校验后直接替换当前简历。因此本技能的产出即可作为最终交付物。

## 不可突破的红线

1. **绝不虚构事实**：公司名、职位、任职时间、项目名、学历、证书、业绩数字，一律以用户提供的素材为准。不得为了"看起来更强"补写任何经历或数字。
2. **数字需确认**：任何量化成果（提升 X%、管理 X 人、营收 X 万）必须由用户给出或明确确认；素材里没有就写成定性描述，不要估算、不要编造占位数字。
3. **占位要显式**：缺失字段用空字符串或 `【待补充：xxx】` 标注，并在回复中列出待补充清单，不得伪装成已填好。
4. **不替用户做职业决策**：不明确指定目标岗位时，只做通用版并主动询问目标方向；不得自行假定用户想转行或跳槽。

## 工作流

### 第 1 步：判定输入模式

| 模式 | 特征 | 处理方式 |
|---|---|---|
| A 从零生成 | 用户给一段自述、聊天记录、或只说"帮我写份简历" | 先做信息收集（第 2 步），再生成 |
| B 改写优化 | 用户提供现有简历（文本/文件/截图） | 保留全部事实，重写表达与结构，输出新旧对照说明 |
| C 按 JD 定制 | 用户同时给了岗位 JD | 提取 JD 关键词 → 映射到用户真实经历 → 调整栏目顺序与总结措辞，不新增未发生的经历 |

三种模式可叠加（如 B+C）。

### 第 2 步：信息收集（一次性问完）

读取 `references/writing-guide.md` 的「信息清单」。把缺失项合并成**一次**提问，按优先级排序：目标岗位 > 真实经历（公司/岗位/时间/做了什么/结果）> 教育 > 技能 > 联系方式。避免逐条挤牙膏式追问。

用户明确表示"随便写个示例/模板"时，生成带明显占位符的样例简历，并在开头声明这是示例、非真实材料。

### 第 3 步：按 HR 视角重写

读取 `references/writing-guide.md`，执行其中的表达规范、JD 关键词映射、废话清单与栏目顺序建议。核心是：把"职责描述"改写成"动作 + 对象 + 可验证结果"，把与 JD 无关的素材降权。

### 第 4 步：组装 JSON 并校验

读取 `references/schema.md`，以 `assets/resume-template.json` 为骨架，组装 schema v3 对象。

**必须执行校验**，避免用户导入时报错：

```bash
python scripts/validate_resume.py "<生成的文件路径>"
```

校验不通过时按错误信息修正后重跑，直到输出 `OK`。校验器复刻了青柠简历 `data.js` 的 `normalizeResume` 规则。

保存为 `<姓名>-简历.json`（UTF-8，无 BOM，`indent=2`），放在当前工作目录。

### 第 5 步：交付与导入指引

向用户交付 JSON 文件，并给出以下操作说明（同时列出第 2 步遗留的待补充项）：

1. 打开 https://cvlime.github.io
2. 点顶部「备份恢复」→「恢复」（或「导入」），选择刚生成的 `.json` 文件
3. 确认替换提示，右侧立即出现排版预览；可切换字号（紧凑/标准/宽松）
4. 点「导出 PDF」→ 浏览器打印对话框里选择「另存为 PDF」，并开启「背景图形」
5. 提醒：该站点数据存在浏览器本地（localStorage），换设备前先点「备份」导出 JSON

## 关键实现细节

- **空栏目必须 `hidden: true`**：青柠简历会自动补齐缺失的内置栏目并默认显示，若不显式隐藏，PDF 里会出现空标题块。
- **`body` 支持 `\n` 换行与 `**文字**` 加粗**：每条经历写成"**小标题**：一句话说明"的格式，一行一条，渲染效果最好。
- **栏目标识**：内置栏目 `id` 必须等于 `kind`（`work` / `projects` / `skills` / `education`）；自定义栏目用 `custom-1`、`custom-2`…，并同步写入 `sectionOrder`。
- **`fontSize` 只能是 12 / 13 / 14**，默认 13。
- `sectionOrder` 决定栏目显示顺序，数组内 id 不可重复、不可指向不存在的栏目。

## 资源

| 文件 | 用途 | 何时读取 |
|---|---|---|
| `references/schema.md` | schema v3 完整字段、长度限制、校验规则与已知坑 | 组装 JSON 前 |
| `references/writing-guide.md` | HR 视角写作规范、信息清单、JD 映射、废话清单 | 第 2、3 步 |
| `assets/resume-template.json` | 可直接填充的空白骨架 | 组装 JSON 时作为起点 |
| `scripts/validate_resume.py` | 本地校验生成的 JSON 能否被青柠简历接受 | 写文件后、交付前，必跑 |

## 扩展方向

- 需要独立 PDF（不依赖外部站点）时，另建渲染脚本，不要改动本技能的数据契约。
- 需要英文简历时，复用同一 schema，另加一份英文表达规范到 `references/`。
