# HR 视角简历写作规范

目标读者是**用 10–30 秒扫一屏的招聘方**。所有规范服务于一个目的：让筛选者在最短时间内确认「这个人能干这件事」。

## 一、信息清单（一次性问完，按优先级）

**必需（缺了就无法成稿）**
1. 目标岗位 / 求职方向（决定全篇措辞与顺序）
2. 真实经历：公司或组织、岗位、起止时间、主要做什么、有无可验证结果
3. 教育背景：学校、专业、学历、时间
4. 姓名、手机、邮箱

**强烈建议**
5. 与岗位相关的技能 / 工具 / 证书
6. 项目经历（尤其技术、产品、运营、咨询类岗位）
7. 所在城市、期望薪资（可写「面议」）

**可选**
8. 个人主页 / GitHub / 作品集
9. 自定义栏目：获奖、培训、志愿经历、语言能力

一次性把缺失项列成一组问题，不要逐条追问。用户说「先随便写个版本」时，用明显占位符并声明为示例。

## 二、真实性红线

- 不虚构公司、职位、时间、项目、学历、证书、数字。
- 不把「参与」写成「主导」，不把团队成果写成个人成果。
- 量化数据必须由用户给出或确认；没有数字就写定性结果（如「缩短招聘周期」而非「缩短 30%」）。
- 不替用户填写未确认的技能熟练度。
- JD 里要求但用户没有的经历：**不写**，也不要用「了解/接触过」模糊带过；在交付说明里提示这是待补的差距。

## 三、表达规范

### 把职责改写成贡献

| 弱写法 | 强写法 |
|---|---|
| 负责公司招聘工作 | 独立承接 5 个部门的社招需求，从需求对齐到 offer 全流程跟进 |
| 参与系统上线 | 梳理上线前的 3 类异常场景并制定回滚清单，上线后零重大故障 |
| 熟练使用 Excel | 用数据透视表搭建周报模板，将统计耗时从半天压缩到 1 小时 |

### 句式

`**小标题**：动作动词 + 具体对象 + 可验证结果/范围`

- 每行一条，`body` 里用 `\n` 分隔；`**...**` 加粗作为行首标签。
- 优先动词：搭建、主导、梳理、交付、优化、推动、协调、复盘、沉淀、落地、拆解、对齐。
- 避免：负责、参与、协助、了解、熟悉（单独出现时信息量近乎为零）。
- 每条经历 3–5 行，单行控制在 40–60 字，避免大段文字墙。

### 个人总结（summary）

3–4 句，顺序固定：
1. 身份定位：`N 年 XX 领域经验，专注 XX`
2. 最强能力 / 最有说服力的成果
3. 与目标岗位直接相关的匹配点
4. 求职意向（一句，克制）

不要写「性格开朗、吃苦耐劳、学习能力强」这类不可验证的形容词。

## 四、按 JD 定制（模式 C）

1. 从 JD 提取三类词：**硬技能/工具**、**业务场景**、**能力动词**。
2. 逐词到用户真实素材里找对应证据，找得到的写入 summary 与对应经历的行首标签。
3. 找不到的列为「待补充/差距」，在交付说明里告诉用户，不要编。
4. 调整栏目顺序：JD 强调项目 → `projects` 提前；强调技术栈 → `skills` 提前；应届生 → `education` 提前。
5. 术语对齐：JD 写「用户增长」就不要写「拉新运营」，用对方的语言，但事实不变。

## 五、栏目顺序建议

| 人群 | 建议 `sectionOrder` |
|---|---|
| 有经验的社招 | `work` → `projects` → `skills` → `education` |
| 技术/产品/设计 | `work` → `projects` → `skills` → `education` |
| 应届 / 实习为主 | `education` → `projects` → `work`(实习) → `skills` |
| 转行 | `skills` → `projects` → `work` → `education`，并在 summary 明确转行动机 |
| 管理岗 | `work` → `custom-1`(管理/团队成果) → `skills` → `education` |

自定义栏目示例：`获奖与证书`、`培训经历`、`语言能力`、`志愿与社会实践`、` publications`。

## 六、长度与版面

- 初级岗位 1 页；5 年以上或项目密集 2 页；超过 2 页要删而非缩字号。
- `fontSize`：内容多用 `12`（紧凑），常规 `13`，内容少可用 `14`（宽松）。
- 时间段格式统一，如 `2022.03 - 2025.06`；在职写 `2022.03 - 至今`。
- 工作经历倒序（最近在前）。
- `skills` 栏目通常整栏只有 1 个条目，`title` / `date` 留空，只写 `body`。

## 七、交付自检清单

- [ ] 所有数字、公司、时间均有用户提供或确认
- [ ] 必填字段齐全且为字符串（无 `null`）
- [ ] 每条经历是「动作 + 对象 + 结果」，无空话
- [ ] summary 与目标岗位对齐，无形容词堆砌
- [ ] 空栏目已设 `hidden: true`
- [ ] `body` 只用 `\n` 与 `**加粗**`，无 Markdown 列表/表格
- [ ] `sectionOrder` 中 id 无重复、全部存在
- [ ] 已通过 `scripts/validate_resume.py` 校验
- [ ] 回复中列出待补充项清单
